# 月清疏 → X4 移植技术记录

记录这次移植里**靠实测得到**、且换来源/换版本就必须重新量的东西。结论一律带判据，
不带判据的结论不写进来。

---

## 1. 源模型：这是"最简单"的一类来源

Pal7 的角色用的是 **3ds Max Biped**，与 X4 是同一个骨架家族：

```
月清疏                              X4
Bip001-Pelvis                    Bip01 Pelvis
Bip001-L-UpperArm                Bip01 L UpperArm
Bip001-L-Finger0  … Finger42     Bip01 L Finger0 … Finger42
Bip001-L-Thigh / Calf / Foot / Toe0
```

差别只是拼写（`Bip001-` 对 `Bip01 `，连字符对空格）。**手指、脚趾、脊柱三节、
锁骨全都有真正的对应物** —— 不像 MMD 来源（275 骨）要造 134 根折叠骨。

| | 套装 A（默认 `MAJ02_01`） | 套装 B（第二 `MAJ02_02`） |
|---|---|---|
| 骨骼 | 191 | 239 |
| 顶点 / 三角面 | 115 401 / 152 331 | 74 751 / 113 242 |
| 带权骨 | 178 | 158 |
| 映射结果 | 52 直接 + 折叠 + 1 未映射（`Bip001`，无权重） | 52 直接 + 105 折叠 + 1 未映射 |

**两套服装共用同一张脸。** 实测：`MI_MAJ02_01_head`(4018/7390)、`_eye`(1600/3072)、
`mouth_Skeleton`(1598↔1600/2866)、`Eyelash_eyebrow`(396/388)、`TearLine`(312/492)、
`Eye_Occlusion`(252/408) 两次导出的顶点数与面数相同，`body` / `hair` 连材质**名字**
都一样（几何不同）—— 只有衣服（`cloth1/2/3`、`tassel`）与发型不同。

## 2. 两个"帧"问题：都只在实机暴露，都必须实测

### 2.1 坐标映射是一次**反射**（det = −1），所以必须反转绕序

判据取自解剖学，不取自拟合：

```
月清疏  Bip001-L-Toe0 − Bip001-L-Foot = (+0.007, −0.090, +0.113)  脚趾落在 +Z
X4      Bip01  L Toe0 − Bip01  L Foot = (+3.79,  +12.96, −11.43)  脚趾落在 +Y
月清疏  Bip001-L-Thigh 的 x = +0.085；X4 Bip01 L Thigh 的 x = +11.61   两边 "L" 同号
```

于是 `(x, y, z)_月 → (x, z, y)_X4`：`y(上) → z(上)`、`z(前) → y(前)`、`x` 原样。
**交换两个轴 = det −1**，每个三角形会朝内 —— 必须反转绕序。

源数据的绕序本身是对的：逐面 `dot(面法线, 顶点法线)` 均值 **+0.99**，正值占 **100%**
（27 个 primitive 全过）。所以问题不在源，在映射。

> `tools/glb.py::winding_report` 就是这条判据；`tools/render_check.py` 默认
> **开背面剔除**，绕序错了会直接渲染成一片空洞 —— 不开剔除的话这个错误完全看不出来。

### 2.2 UV 存 `1 − v`：用提取仓库自己的 `.blend` 逐值核对

glTF 与 DX 一样把 v=0 放在图像顶端，Blender 放在底端；导出器自己还会做一次
`1 − v`。所以 Blender 里必须存 `1 − v_src`。

**判据不是推理，是对照现成的产物**：提取仓库里那份 `.blend` 的贴图装配是对的
（它的预览渲染五官正常），直接读它的 UV 范围来比：

```
glb 原始     u[0.0000, 1.0000]  v[0.0000, 1.0098]
1 − v_glb    v[−0.0098, 1.0000]
原 .blend    u[0.0011, 0.9985]  v[−0.0098, 0.9988]   ← 与 1−v 吻合（上界略小是因为它删了隐藏面）
```

`v` 的下界 **−0.0098** 两边逐位相同，这是决定性的：原 `.blend` 存的就是 `1 − v_glb`。

## 3. 贴图：源目录里的贴图**不都是能直接用的**

Pal7 的头部基础色是**叠加图**：只有五官画了颜色，其余整片是纯黑（
`T_MAJ02_01_head_D.png` 的 alpha 有 85.5% 小于 8，RGB 下半幅全黑），
因为游戏里其余部分由皮肤着色器补。**直接用会让额头/下巴/脖子渲染成黑块。**

提取仓库的 `fix_head_texture.py` 已经把黑区洪水填充成肤色、另存 `*_skin.png`，
并把虹膜盘合成到巩膜上另存 `*_eye.png`（着色器把两者相乘，而虹膜图外围是黑的，
原始两张一起用会得到一个纯黑的眼球）。

**判据不是看文件名，是读原 `.blend` 的材质节点**：

```
原 .blend  MI_MAJ02_01_head → T_MAJ02_01_head_D_skin.png     （不是 T_MAJ02_01_head_D.png）
           MI_MAJ02_01_eye  → S_EyeScleraBaseColor_eye.png  （不是 S_EyeScleraBaseColor.png）
```

**法线与粗糙度是作者画的**，这是相对 MMD 来源最大的优势：
`_N` → BC5（不生成假的平面法线），`_ORM` 的绿通道 → `smoothness = 1 − roughness` → BC4。
只有 `eyelash` / `eyeocc` / `tear` 三个材质没有任何贴图（颜色全在 shader 参数里），
给它们一张纯色占位 —— **导出器要求每个材质都有 Diffuse 节点**，缺一个就是
`XacError: missing required texture node: Diffuse`。

## 4. 骨架：必须和**各自的宿主**比

第一次把两个 `.xac` 都拿去和 `char_arg_f_dyn_blend_head.xac` 比，body 只有
**39/91** 相同，看起来像"骨架被改坏了"。实际是基准选错了：

```
yue_a_head.xac  vs  char_arg_f_dyn_blend_head.xac          91/91 ✓
yue_a_body.xac  vs  char_arg_f_jacket_leggings_civ_01.xac  91/91 ✓
yue_a_body.xac  vs  char_arg_f_sweater_leggings_civ_01.xac 21/91 ✗
```

**vanilla 的 head 资产与 body 资产骨架序列化并不相同，两个 body 资产之间也不同。**
替换哪个资产，就和那个资产比。

> 这条教训顺带修掉了 `verify_mod.py` 里的一个**真实缺陷**：它写死了 sweater 作
> body 基准，于是会对完全正确的产物报 FAIL。修法是把基准改成 `paths.HOST_BODY`，
> 与管线共用同一个定义 —— 判据与管线共享配置，就不可能再分歧。

## 5. 顶点预算与减面：12× → 3.3×/3.9×

源 115k 顶点对 vanilla 两个资产合计约 9.6k = **12×**，远超"15.5× 就开始频闪"的
警戒线。用户选了"优先稳定"，目标定在 vanilla 的 3–6 ×：

| | 减面后 | vs vanilla |
|---|---|---|
| A head | 19 166 | 3.83× |
| A torso | 15 781 | 3.43× |
| B head | 16 034 | 3.21× |
| B torso | 17 031 | 3.70× |

比例表在 `yue_src.DECIMATE`。原则：**头发与睫毛砍得最狠**（0.20 / 0.15），它们是
成片的发卡条带，砍一半看不出来；**脸保留最多**（0.70），那是玩家真正盯着看的地方。

**这个来源不怕减面**：贴图是**按材质分张**的（不是 MMD 那种共享图集），
UV 偏移只会读到同一张图内的邻近区域，不会串到别的部件上去。

## 6. "两脚间距"：判据是几何，不是骨骼

第一版按技能推荐的 **0.60 / 0.85 / 0.95** 横向阻尼建出来，量到两脚间距只有
vanilla 的 **76%**（25.2 对 33.1 cm）—— 按判据这是**猫步**。

但骨骼位置是对的：

```
mod  Bip01 L Thigh X=11.61  Calf X=14.81  Foot X=17.70  Toe0 X=21.50   （与 vanilla 逐位相同）
```

再用 Blender 量**绑定姿态的脚部几何**（按权重取 `Foot`/`Toe0` 的顶点）：

```
左脚顶点 X[13.16, 22.39]，重心 X=15.7 —— 比脚骨（17.3）**向内偏 1.6 cm**
```

**结论：阻尼设的是骨的目标位置，而判据量的是几何。** 月清疏的脚几何相对它的脚骨
向内偏，所以骨落在 vanilla 的位置时几何仍然偏窄。

修法是把脚的目标**再往外推**（阻尼 > 1）：

```
0.60 / 0.85 / 0.95  →  两脚间距 76% / 78% / 81%
0.80 / 1.00 / 1.20  →  两脚间距 89% / 91% / 91%      ← 采用
```

撕裂没有恶化（141% → 140%），骨链仍然**单调外撇**（10.9 → 14.8 → 19.3），
这是技能里"横向阻尼不能沿链递减"那条规则的直接检验。

## 7.5 「不该被看见的层」：靠 alpha 表达的东西，在单值 blendmode 下只能丢

提取仓库的 `.blend` 里有三件材质，它们的"不可见"是**用 Blender 的 alpha 表达的**：

```
eyelash_new_Inst            alpha = 0.35   12074 面   睫毛卡片（在眼睛高度，y[1.532,1.549]）
MI_MAJ02_01_Eye_Occlusion   alpha = 0.00     408 面   眼窝遮蔽（y[1.534,1.547]）
MI_MAJ02_01_TearLine        alpha = 0.15     492 面   泪线（y[1.532,1.546]）
```

第一版给它们各发了一个**不透明**的占位色（睫毛深棕、遮蔽米色、泪线近白），
渲染出来是**两只眼睛上方各一块米色斑 + 一圈深色**，远看就是"浓重眼线 / 粗眉"。

**修法与判据**：

* `Eye_Occlusion` / `TearLine` → **丢弃**。X4 的 `blendmode` 是单值（`NONE` /
  `ALPHA8` / `ADDITIVE` / `ALPHA1` / `SCREEN` / `TWOSIDED`，没有组合值），
  而"淡"对一件同时还得双面的几何不可表达；alpha≈0 的东西丢掉是等价的。
* `eyelash_new_Inst` → **`ALPHA8` + 占位图里烙进 alpha=0.35**。这一件必须保留
  （否则没有睫毛），而它贴在眼球上、极少被从背面看到，所以放弃双面的代价
  小于收益。

顺带把占位色也改成从 `.blend` 的 Principled 基础色取，而不是自己估：
`eyelash` 是 `(0.07, 0.05, 0.02)` → 8 位 `(20, 14, 6)`。

> 教训：**"这块颜色不对"要先用 `render_check.py --hide <stem>` 分材质出图**，
> 把可疑件逐个摘掉，看症状跟着谁走。我一开始以为是眉毛（`MAJ02_01_Eyelash_eyebrow`，
> 396 顶点，在眉毛高度 y[1.551,1.560]），摘掉才发现真凶是眼睛高度那两片 alpha 层。

## 7.55 横向阻尼改的不是位置，是**每一段的倾角**

这是这一轮最贵的一课。用户的原话是"初版正常的腿是个倒 V，第二版腿在 V 中间
折了一下"。

先看**骨骼**：`adjust_target` 调的是**重定向的目标**，骨架本身永远是 vanilla 的
（stage1 里导入的宿主骨架），所以量骨骼永远量不出问题 —— 骨链一直是

```
Thigh 11.61  Calf 14.81  Foot 17.70  Toe0 21.50    斜率 +0.0738 / +0.0738   （直线）
```

真正变的是**每一段的目标位置**，几何从目标重建，所以倾角随目标走。把每段的
目标位置除以它跨越的高度，得到的就是那一段的倾角：

| | 大腿段 | 小腿段 | **两段之差（折角）** |
|---|---|---|---|
| 初版 `0.60/0.85/0.95` | 4.30° | 4.75° | **0.45°** 看不出 |
| 第二版 `0.80/1.00/1.20` | 4.80° | 6.45° | **1.65°** 3.7 倍，一眼可见 |

**折角 = 相邻两段倾角之差**。第二版是照着"两脚间距要接近 vanilla"（89–91%，
指标达标）调出来的，但把小腿段单独加码，两段之差就放大了。

> **指标对不等于形状对。** "两脚间距"这个比值只约束**两个端点**；腿的形状约束的
> 是**整条链**。用端点比值去调链上的参数，很容易调出一个端点达标、中间折断的解。

**回退到初版**（`0.60/0.85/0.95`）后折角回到 0.45°。代价是两脚间距回到 vanilla
的 76–84% —— 这是已知取舍，**形状优先**。真要拉宽站姿而又不折弯，得让**整条链
一起**线性外推（即保持斜率不变地整体平移），而不是给某一段单独加码。

## 7.6 长裙 vs 横向阻尼：套装 B 的腿穿出裙子

修"猫步"的横向阻尼（§6）把腿推到了 vanilla 的站姿宽度上。这对套装 A 无害 ——
它的短裙只到大腿中部，腿在裙外本来就是裸露的（原作预览可证）。**套装 B 不是**：
它的紫蓝长裙盖过大腿中下部，腿一外推就从裙子两侧顶出来。

**判据（`tools/diag_leg_clip.py`）**：按高度分层，比**腿的外缘**与**同侧裙子侧壁
的外缘**。这里连错两次，两次都是尺子的问题：

| 写法 | 结果 |
|---|---|
| 不分左右，`min(全部裙子 x)` 当"裙内缘" | 拿到对侧裙子的外缘（负值），"穿模"算出 44–66 cm |
| 分左右，但取 `min(同侧裙子 x)` | 拿到**垂在两腿之间的前襟**（x≈0），仍算出 16–19 cm |
| **取 `max(同侧裙子 x)`（侧壁外缘）** | 合理：B 在 z=53–77 段穿模 2–5 cm，最大 **5.19 cm** |

> 同一个"腿穿出裙子"，三个判据给出 66 / 19 / 5 三个数量级完全不同的答案。
> 前两个都不是"精度差一点"，而是**量错了对象**。

**第一版修法是"把腿收窄"（`LEG_SHRINK = 0.55`）——已经废弃。** 它把穿模数字
修好了（5.19 → 1.62 cm）但腿的形状读起来不对，而且**方向本来就反了：不合身的
是衣服，不是腿**。

**现在的修法是"把裙子放阔"**（`yue_src.SKIRT_WIDEN`，B = 1.30）：

* **按高度渐变，腰部一动不动** —— 腰贴着腰带，推出去会穿模；
* **限定在一条高度带里**（`SKIRT_WIDEN_BAND = (50, 85)`，两端羽化 6 cm）。
  这一条是踩出来的：`cloth1/2/3` 是**整套服装**的材质而不是"裙子"，它们的顶点
  从 z=190（披肩、立领）一直铺到 z=−1（靴底）。整块放阔会把上衣、披肩和靴子
  一起放大 —— 第一版就是这么干的，最大位移 8.63 cm **全在靴子上**，而带内只有
  1526 个顶点（真正的裙子，`cloth3` 是它的大头）；
* 放大以 **x=0（身体中轴）** 为中心：`x_new = x * k(z)`。

```
最大穿模 5.19 cm -> 除 z=77 单层（该层裙子顶点稀疏，取到的 max 是采样假象）
                    外，所有层均为负值（-0.2 ~ -6.3 cm），多数还有余量
两脚间距 0.90-0.93x -> 0.76-0.84x（跟随横向阻尼一起回到初版，见 §7.55）
腿的形状 折角 1.65° -> 0.45°（倒 V 恢复）
```

## 8. 这次踩到的坑（按代价排序）

1. **头部叠加图**（§3）：直接用 `T_MAJ02_01_head_D.png` 会让整张脸发黑。
   第一次渲染出来的脸是深棕色的，靠**分材质隐藏**（`render_check.py --hide`）
   才定位到是 head 材质而不是睫毛盖住了脸。**判据是读原 `.blend` 的材质节点。**
2. **骨架基准选错**（§4）：会对正确的产物报 FAIL，然后你会去"修"一个没坏的东西。
3. **两脚间距量的是几何**（§6）：骨对了不等于形对了。
4. **`verify_mod.py` 的 `configure()` 签名**：组装脚本的模块级状态由它绑定，
   自检脚本必须用**同样的参数**调一次，否则 add 形态的池检查会去读 `None`。
5. **导出器的包路径**：`write_package()` 把每个 `.xac` 都写进 `bodies/`，
   它没有 head/torso 的概念 —— 组装时要按文件名重新归位到 `heads/` / `bodies/`。
6. **包名 / macro 名必须一致**：`make_mod.OUTFITS` 的别名要和
   `build_yue_mod.ASSET_PATH` 生成的包名对得上。对不上时最容易做的是"顺手改名让
   脚本跑过去"，而那会让 macro 指向不存在的路径 —— 实机表现是**没有模型**，
   且不报任何错。
